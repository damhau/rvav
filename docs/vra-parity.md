# rvav compared with vRA 8

This page compares rvav with vRA 8 (Aria Automation 8.x) feature by feature,
as an organisation that runs vSphere only uses vRA. It was made on
2026-11-18, at commit `9017462`, and is counted again as each parity
milestone closes: Cloud Assembly's rows after T1, the forms' rows (A8,
A9, A11 to A13, D6) after F1, and the deployments' rows (A19, B1 to B3,
B5, B7, B13, B15 to B18, B22, B27) after X1, all on 2026-11-19, the
access rows (A7, A20, A28, A29, B4, C5, C6, D15) after G1, and the
requesting rows (A1, A2, A15, A23, A26, A27, A29, B11, B15, B21, C7)
after C2, the same day, and the extensibility rows (B19, C27, D1, D2,
D4, D8, D9, D11) after E1, and the platform rows (A31 to A33, A35, D18,
D19, D21) after O1, on 2026-11-22.

It counts in finer detail than [section 3 of the implementation
plan](implementation-plan.md#3-what-80-of-vra-means). That table has 50
features and credits each one in full once its slice is built. This page
splits vRA into 129 features and checks each part of each feature in
rvav's code and tests.

## How features are rated

Each vRA feature has a weight for how much a vSphere shop relies on it:
H = 3, M = 2, L = 1. rvav gets one of these ratings for it:

- **Full:** rvav gives the same outcome. The mechanism can differ, for
  example AWX where vRA uses vRO.
- **Partial:** rvav has some of it. The row says what is missing.
- **None:** rvav has nothing for it.
- **Out:** rvav decided not to do it. These are other clouds,
  multi-tenancy, Kubernetes and Tanzu, Code Stream, native Terraform, cost
  and showback, NSX load balancers, and scripting in workflows.

A rating comes from the code and its tests, not from rvav's docs. Each
row names the files and tests it was checked against. Real infrastructure
isn't part of this comparison: rvav is tested against vcsim and fakes of
AWX, EfficientIP, vRA and NSX, and the
[Lab acceptance](https://github.com/damhau/rvav/milestone/9) issues track
the real systems.

Coverage is the share of the total weight that rvav covers. A Full
feature counts its whole weight, a Partial one counts half, and None and
Out count nothing.

plan asks whether each area of vRA is built. This page asks what an
administrator or requester who knows vRA would find missing.

## Beyond vRA

What rvav does that vRA 8 doesn't:

- **A preview before submitting:** the names, next free IP, cluster,
  datastore and folder, the quota left and the approval that applies.
- **Approvals in Teams and Slack,** delegation, and approvers who can lower
  what was asked for.
- **Drift:** a VM changed in vCenter is flagged with what differs, and can
  be accepted as it is.
- **Live inventory:** each vCenter's changes are followed as they happen,
  not collected on a timer.
- **Names checked before they're given,** in vCenter, DNS and rvav, and
  unique under concurrent requests.
- **EfficientIP and DNS throughout,** onboarding included, with a report
  of addresses and records no deployment owns.
- **The catalog in Git both ways:** rvav commits what it publishes, and
  changes in the repository become drafts.
- **Subscription runs you can trace and retry,** and webhooks signed with
  HMAC as targets.
- **Explanations:** what policies apply here, and why someone may do
  something.
- **Upgrades and setting changes without downtime,** with requests in
  flight kept.
- **An importer for vRA,** and a triage of the vRO content.

## vRA behaviour to confirm

These rows rest on what vRA 8 is believed to do. The organisation's vRA
administrators can confirm them:

- A14: whether custom forms take CSS.
- A17: whether Service Broker has requests on behalf of someone and
  scheduled requests.
- A23: whether an extension past the maximum total lease is refused
  (rvav's hard lifetime asks for approval).
- A26, A27: whether a quota's user level in a policy for every project
  limits each project on its own (rvav's **Each user across rvav** adds
  them up), and whether deployment limit policies' storage and criteria
  are used.
- B8: whether a snapshot can be quiesced.
- B14: whether there's a change network action outside Update.
- B20, B23: whether day-2 actions run on several deployments at once, and
  on discovered machines.
- C9: whether image mappings take cloud-init and constraints.
- C30: whether `deleteBehavior` is a cloud template flag.
- D15: whether a project supervisor may do more than see the project's
  deployments and approve.
